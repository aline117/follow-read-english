## Context

这是一个全新项目，目标平台为 iPad（iOS 18+），使用 SwiftUI 构建。核心用户为小学生（6-10岁）及其家长。项目需要支持音频播放/录音、本地数据持久化、多用户 Profile。

## Goals / Non-Goals

**Goals:**
- 构建 iPad 原生 APP，支持横竖屏
- 实现核心学习循环（学单词：听·认·说合练 → 游戏 → 句型 → 复习）
- 实现虚拟+现实激励系统
- 实现家长控制面板
- 支持多孩子 Profile

**Non-Goals:**
- 不做 Android/Web 版本
- 不做在线社交功能
- 不做 AI 自适应算法（首版用固定间隔重复）
- 不做内容创作工具（内容由运营录入）

## Decisions

### Decision 1: SwiftUI + SwiftData

**选择：** SwiftUI 作为 UI 框架，SwiftData 作为本地持久化。

**理由：**
- SwiftUI 原生支持 iPad 大屏幕、拖拽、动画
- SwiftData 与 SwiftUI 深度集成，适合本地数据模型
- 无需第三方依赖，降低维护成本

**备选：** UIKit（更成熟但代码量大）、Core Data（更复杂）、Realm（第三方依赖）

**落地约定（2026-10 补充）：**
- 部署最低版本锁定 **iOS 18**（SwiftData 需 iOS 17+；18 起可用 `#Unique` / `#Index`，进度表复合唯一键依赖它）
- SwiftData 只存**可变数据**（学习状态 + 家长配置）；**只读课程内容不进库**，启动时解码 `gradeN.json` 一次并常驻内存
- 因此不再需要 `CurriculumCourse` / `Lesson` / `Word` / `Sentence` 这四个内容型 `@Model`，内容改为纯 `Decodable` struct（详见 Decision 6）

### Decision 2: 音频方案

**选择：** AVAudioPlayer 播放 + AVAudioRecorder 录音 + **设备端语音识别对比（见 Decision 18）**；**配速分 0.5x / 0.75x / 原速三档，用 `AVAudioEngine` + `AVAudioUnitTimePitch` 保音高**。

**理由：**
- 系统原生框架，无需第三方
- 评测用系统 `SFSpeechRecognizer` 的设备端识别把录音转文本，与目标词比相似度；音量/时长只做兜底，不接第三方 SDK
- 三档都用 `AVAudioUnitTimePitch` 实时变速不变调；`AVAudioPlayer.rate` 会**同时降低音高**，对儿童辨音不利（代价是多一层 engine 配置，约半天）

**备选：** 接入讯飞/百度语音评测 API（更准确但增加依赖和成本）；接受 `AVAudioPlayer.rate` 的变调效果（实现最简单，但慢速时的音色明显失真）

### Decision 3: 内容数据管理（零内置 + 家园局域网下载）

**选择：** App 内**不打包任何课程媒体或词表**，只内置一份几 KB 的 `catalog.json`（学期目录：标题、大小、版本，无内容本体）。学习内容由家里的电脑通过局域网 HTTP 服务按学期下发，iPad 下载后存本地。

**理由：**
- **内容与代码解耦**：新增二下 / 三上不需要重新构建安装 App。自用侧载没有体积限制，省体积本身不是目的，能独立更新内容才是
- 家园局域网带宽充足（约 50MB 的学期包十几秒传完），无需断点续传、CDN、灰度
- 不上架、不走 App Review，本地 HTTP 服务足以承担分发
- 孩子日常学习仍然完全离线：已下载的学期不依赖网络

**取舍：**
- 首次使用与每次开学季都需要"家里电脑开机 + 同一 Wi-Fi"，作为家长 runbook 明示
- 家里电脑成为唯一内容源 → 学期包与管线脚本必须异地备份（见 Risks）

**备选：** 全量内置（简单，但加内容必须重发版）、On-Demand Resources（需 App Store/TestFlight 分发，自用不可用）、自建公网对象存储（多一层成本与安全面）

### Decision 4: 激励系统架构

**选择：** 本地存储星星/积分/徽章，家长端管理兑换规则。

**理由：**
- 首版无需服务器，数据本地存储
- 兑换审核由家长在 APP 内完成
- 后续可扩展为云端同步

### Decision 5: 多 Profile 支持

**选择：** 基于 SwiftData 的 Profile 模型，每个 Profile 独立数据。

**理由：**
- 简单直接，无需复杂权限系统
- 家长可切换查看不同孩子数据

**生命周期（必须实现，否则会留孤儿数据）：**
| 动作 | 行为 |
|---|---|
| 创建 | 首次启动引导创建；家长 Tab「孩子切换」里可再加（上限 4 个） |
| 切换 | 学习/奖励/家长三个 Tab 全部按 `profileID` 过滤；当前选中 `profileID` 持久化（`@AppStorage`），重启后保持 |
| 删除 | 家长确认后按 `profileID` **逐表批量删除**：`ItemProgress` / `Attempt` / `LearningSession` / `ReviewSchedule` / `StarLedger` / `Badge` / `Redemption`（`ProfileDataPurger`，幂等）；至少保留 1 个 Profile，不允许删最后一个 |
| 升年级 | 家长 Tab 改 `Profile.grade` → 首页列出对应 catalog 学期；已下学期的进度按 `itemCode` 保留，不因换年级清空 |

**为什么不用 `@Relationship(deleteRule: .cascade)`：** 各表用裸 `profileID` 才能按内容码直接过滤与批量查询；cascade 需要为 7 个模型都维护反向关系，且裸 UUID 模型上它不会自动生效。数据量很小（一年 1-2 万行），手动 purger 更可控、也便于写单元测试。

### Decision 6: 数据分层与内容身份

数据按"谁写入"分三层，只读内容不进数据库：

| 层 | 存放 | 成员 |
|---|---|---|
| 只读内容 | 内置 `catalog.json` + 下载的学期包（`Application Support/Curriculum/<semester>/`），解码后常驻内存 | `Catalog` / `Volume` / `Unit` / `UnitWord` / `Listening`（纯 `Decodable` struct，无 `@Model`） |
| 学习状态 | SwiftData | `Profile` / `LearningSession` / `Attempt` / `ItemProgress` / `ReviewSchedule` / `StarLedger` / `Badge` / `Redemption` |
| 家长配置 | SwiftData + Keychain | `RedemptionRule` / `LearningSettings`（每个孩子一份练习强度设置）/ `ParentProfile`（最多 2 位家长，共用 PIN）；家长 PIN 存 Keychain（salt + 哈希，不存明文） |

**键规则（唯一一条，避免两套 id 打架）：**
- 内容实体一律用课本**业务码 String**：`UnitWord.id = "758201"`、`Sentence.id = "s1"`、`Unit.id = "u1"`、`Volume.id = "shangce"`
- **item 统一编码**（单词与句型共用同一套进度/复习/评分表）：`itemCode = "w:<wordId>"`（`w:758201`）或 `"s:<unitId>-<sentenceId>"`（`s:u1-s1`）
- 本地生成的实体一律用 **UUID**：`Profile.id`、`LearningSession.id` 等
- 跨层关联只走业务码 String：`ItemProgress.itemCode`、`ReviewSchedule.itemCode`、`Attempt.itemCode`、`LearningSession.unitCode` + `volumeCode`
- 唯一性：`ItemProgress` 用 `#Unique([\.profileID, \.itemCode])` 保证「一个孩子 x 一个条目」唯一；`Attempt` 不做唯一约束（明细允许重复）
- `WordProgress` 重命名为 **`ItemProgress`**（语义覆盖 word / sentence），并带 `itemKind: String`（`word` / `sentence`）便于按类型统计

**奖励记账：** `Reward` 聚合模型取消，改为 `StarLedger` 流水（`grantKey` **按 profile 唯一**保证幂等；入库值带 `<profileID>|` 前缀，老数据裸 key 由查询兼容），余额与"今日已发"由流水聚合，`earnedToday` / `lastEarnDate` 字段不再需要。

**理由：** JSON 解码不产生 UUID，若进度表存 UUID 则永远关联不到真实单词（历史缺陷）；业务码同时是排查内容问题的天然标识。

## Risks / Trade-offs

- [语音评测不准确] → 设备端识别 + 编辑距离只做单词级"像不像"判断，UI 不显示分数；识别不可用时降级为音量+时长，并明确那是兜底而非发音评分
- [内容制作成本高] → 首版只做 2 年级课本，验证模式后再扩展
- [音频素材来源] → 使用网络免费/付费音频资源，避免 TTS 生硬问题和自行录制质量
- [项目性质] → 个人项目，首版免费，暂不考虑商业合规要求
- [儿童隐私合规] → 语音数据仅本地处理，不上传服务器
- [家长参与度不确定] → 设计简洁的家长面板，降低使用门槛
- [内容源单点] → App 内零内容本体，家里电脑是唯一来源；`packs/*.zip` 与 `build_resources.js` / `jx_audio_manifest.json` 必须异地备份并纳入版本库，原始素材依赖第三方站点、可能无法重爬
- [首次使用门槛] → 家长需先在家启动内容服务才能下到第一个学期；用空状态页 + runbook + 引导文案把门槛降到最低，并把学期包做成一次下载长期可用

## Migration Plan

1. 新增学期内容：`build_resources.js` 打成 `packs/<id>.zip` → 放进家里电脑的 `packs/` → App 端拉 manifest 后按需下载，**不需要重新构建 App**
2. 用户数据本地存储，覆盖安装保留容器，无需迁移
3. 后续若上架 App Store，可把家园局域网分发替换为 ODR 或对象存储；切换点只在 `ResourceLocator` 与下载服务，内容包结构不变

## UI / 交互设计

### 导航结构（两种模式，不是一个 tab 里的三个页）

**孩子模式**（默认，打开 App 就是这个）底部只有 **2 个 Tab**：

- **学习**：今日任务卡（20 分钟目标 + 进度条）、继续学习按钮、复习提醒 → 单元列表（按课本 Unit 顺序，**未解锁单元置灰不可点**）→ 学习单元页（含「跟我读」课文原声入口：连播 + 逐条跟读，可选 0.5x / 0.75x / 原速）
- **奖励**：星星余额 + 徽章墙 → 兑换商店（家长启用的规则卡片）→ 申请兑换 → 等待审核状态；防沉迷提示语常驻底部
- **顶栏右上角一个 🔒 小图标 = 家长模式入口**（无文字）：孩子不会去点，家长一戳就知道

**家长模式**（验证后以 `fullScreenCover` 盖上来，独立 `NavigationStack`，**不显示孩子的底部 Tab**）：

- 首页 6 项：学习报告 / 奖励库 / 练习强度 / 内容管理 / 孩子档案 / 设置与安全
- 顶部固定「退出家长模式」，退出不需再验证
- 危险操作（删除学期包、删除孩子、重置 PIN）需二次确认
- 每次进入/退出写审计日志；进入时选"我是妈妈/爸爸"（**仅用于审计**，不额外验证）

首次启动仍走家长配置流程（建孩子档案 → 设 PIN → 选内容下载）；完成页明确提示"以后点右上角的小锁进入家长模式"。

### 家长档案与通知

| 项 | 设计 |
|---|---|
| `ParentProfile` | 最多 2 个（妈妈 / 爸爸），字段 `name` / `avatar` / `isActive`；**共用一组 PIN**（不再多一套密码负担），选择身份只为审计 |
| 审核记录 | `Redemption.reviewedBy` 记录是谁审核的（如"妈妈同意了"） |
| 本地通知 | 兑换提交 → 通知家长去审核；学期包下载完成 → 通知（`UNUserNotificationCenter`，无网络依赖） |
| 审计日志 | 家长模式进入/退出、PIN 重置、恢复码重新生成，均可查 |

### 学习单元流转（约 9-10 分钟/单元，含 1 条句型）
| 环节 | 时长 | 界面要点 |
|---|---|---|
| 学单词（听·认·说合练） | 3min | 左栏大图+单词+中文+听原音（**0.5x / 0.75x / 原速**，新学默认 0.75x）；右栏麦克风跟读，录完和原音对比，不达标给原因+建议配速+纠正方法，达标自动换下一个词 |
| 游戏 | 2min | 听音选 4 图 |
| 句型 | 2min | 听整句（默认 0.75x，可切）→ 跟读整句 → 词块排序（当日新学 1 条句型） |
| 复习 | 1min | 翻卡，**默认原速**（检验真实语速下的辨识），可切 0.75x / 0.5x |
| 结算 | — | 星星动画 + 徽章弹窗（如有） |

环节顺序固定为：学单词（听·认·说） → 游戏(词) → **句型** → 复习。句子不单独开"第 5 个环节"，作为一个组合块插在游戏与复习之间。

**「认」并进「说」（2026-10-27 用户决定）：** 单词的「认」不再单独做拖拽配对，改为「看大图认词」和「跟读」同屏完成，形成"听 → 觉得会了 → 读一遍 → 和原音对比 → 达标自动下一个"的循环。状态机、判定口径、数据写入与异常处理见下节「单词跟读（认·说合练）」。

**「已学」口径随之收紧：** 只有 `ItemProgress.firstPassedAt != nil`（跟读达标过）才计入首页/课程列表的已学进度；只试过没达标不算（口径细节见「指标口径与数据字典」）。

**两个跟读入口的分工（避免混用）：**
- **主流程内**：单词跟读、句型跟读（`itemCode` 驱动，计入进度与复习）
- **「跟我读」（单元页入口）**：课本原声连播 + 逐条跟读，属"额外听力练习"，**不写入 `ItemProgress`、不参与复习调度**，只把"已跟读条数/次数"汇入当日学习数据

### 单词跟读（认·说合练）

> 2026-10-27 用户决定：单词的「认」和「说」合并，一个循环完成"听 → 认 → 说"。

**为什么合并**

| 原三环节 | 问题 |
|---|---|
| 听（1min）→ 说（1.5min）→ 认（1.5min） | 同一个词被拆到三屏，6-10 岁孩子要反复切换状态；"认"的拖拽配对只能验证认得图，验证不了读得出来；跟读与原音不在同一屏，听完就忘 |

合并后：一屏里看图认词、反复听原音、随时读；读完立刻与原音对比，达标自动进入下一个词。

**状态机**

| 状态 | 进入条件 | 界面 | 出口 |
|---|---|---|---|
| `listening` | 进入单词 / 上一个词达标 / 取消录音 | 大图 + 单词 + 中文 + **0.5x / 0.75x / 原速**配速 | 点麦克风 → `recording` |
| `recording` | 麦克风权限已给 | 红色麦克风（点击停止）+ 实时波形 + 倒计时 | 手动停止 / 到上限自动停 → `assessing` |
| `assessing` | 录音结束 | "正在和原音对比…" + 进度指示 | 结论 → `passed` / `failed`；8 秒超时 → 提示重试 |
| `passed` | 判定达标 | 绿色"和原音很像！"+ 听到的文本 | 1.4 秒后自动进入下一个未达标词；没有下一个 → 下一环节（游戏） |
| `failed` | 判定未达标 | 橙色"再来一次"+ 原因 + 建议（含建议配速按钮）+ 差异提示 | 重录 → `recording`；连续 N 次 → 显示「先跳过」 |
| `denied` | 麦克风被拒 | 说明卡（去设置 / 先跳过） | 跳过 → 下一个词（不计已学） |
| `summary` | 主动结束，或整个单元（含游戏 / 句型 / 复习）完成 | 达标数 + 星数 + 词单 + "完成" | 返回单元 / 首页 |

- 录音上限：`min(9, max(4.5, 原音时长 + 2.5))` 秒；到点自动停，避免短语被截断或孩子忘点停止
- 达标后停留 1.4 秒：够看清"和原音很像"，又不让孩子干等
- 从中间某个词进入（单元页点词卡）：按"当前词 → 后面的词 → 回头补前面没达标的词"走，直到全部达标或主动结束
- 从首页「开始学习」进入：从本单元第一个没达标的词开始
- 单元已全部达标过（`firstPassedAt` 都有值）时再次进入 = 练习模式：本次所有词都要过一遍，结算文案用"本次达标 N 个词"，不重复发"首次达标"星

**「听」不是独立环节，就在「说」这一屏里**

- 每个词进入即自动播放原音；图片、单词、"再听一遍"都可点播，配速控件常驻在跟读面板顶部
- 孩子可以反复听、换配速听，觉得会了再点麦克风；结果卡上仍能一键"听原音 / 我的录音"对比
- 复习环节同样听与说同屏，只是默认原速
- 因此环列表里不再有单独的「听」，「学单词」这一屏同时覆盖听、认、说

**配速（0.5x / 0.75x / 原速）**

| 项 | 规则 |
|---|---|
| 档位 | 三档分段控件：`0.5x`（最慢，用来听清开头 / 尾音）、`0.75x`（新学默认）、`1.0x` 原速 |
| 默认 | 新学单词 0.75x；复习 1.0x；「跟我读」1.0x |
| 记忆 | 本次「学单词」内记住最近一次选择（含纠错建议按钮触发的切换），后续词沿用；进入复习或退出学习页后重置 |
| 实现 | 运行时 `AVAudioUnitTimePitch` 变速不变调，不预生成慢速文件 |
| 录音 / 评测时 | 配速控件禁用（录音优先），避免抢音频会话把录音掐断 |
| 建议配速 | 只在失败卡上作为按钮出现：点了才切并播放，**不自动改**，避免打断孩子 |

**判定口径（和原音对比）**

| 检查 | 通过条件 | 不通过文案 |
|---|---|---|
| 音量 | 峰值 > -35 dBFS 且有声采样 ≥4% | 声音太小啦，靠近 iPad 一点 |
| 时长 | ≥ 0.25 秒 | 还没读完呢 |
| 语音识别 | 设备端 `SFSpeechRecognizer(en-US)`，`requiresOnDeviceRecognition = true`，`contextualStrings` 带目标词 | — |
| 相似度 | 归一化（大小写 / 标点 / 空白）后编辑距离相似度 ≥ 0.7；取所有候选里的最高分 | 再跟着原音读一遍（附"听到的是「…」"） |
| 达标 | 音量 ∧ 时长 ∧ 相似度 | — |

- 多词短语（`toy plane` / `play with lanterns`）用整串比较，空白差异不计错
- **不显示准确率百分比**：儿童场景里"89 分"会被当成结论，识别结果本身也不是发音评分；只给"像 / 不像 + 哪里不对"的定性反馈
- 识别权限被拒 / 设备不支持设备端识别 / 听写资源未下载 → 降级为「时长比 0.4–2.5 + 音量达标」，只作兜底，不宣称是发音评测
- **评测基础设施异常 ≠ 读错**：识别超时、音频读不出、录音被系统打断 → 提示"再试一次"，**不写 `Attempt`**；只有"评测跑完但没达标"才写失败明细

**跟读评测参数（集中一处定义）**

| 参数 | 取值 |
|---|---|
| 音量下限 | 峰值 -35 dBFS，且有声音采样占比 ≥4% |
| 最短录音 | 0.25 秒 |
| 达标相似度 | ≥ 0.7 |
| 诊断分界 | < 0.4 完全听错；0.4–0.7 有点接近 |
| 降级时长比 | 原音的 0.4–2.5 倍 |
| 录音上限 | `min(9, max(4.5, 原音时长 + 2.5))` 秒 |
| 识别超时 | 8 秒 |
| 达标停留 | 1.4 秒后自动进入下一个词 |

**失败原因与纠错建议**

失败卡固定三段：① 一句原因（来自判定）② 怎么改（最多两行，带建议配速）③ 差异提示（"听到的是「…」"，并标出与目标词不一致的位置）。

| 诊断 | 触发条件 | 标题 | 建议（含配速） |
|---|---|---|---|
| 太小声 | 峰值 ≤ -35 dBFS 或有声采样 <4% | 声音太小啦 | 靠近 iPad 大声读；先 0.75x 听一遍再读 |
| 没读完 | 时长 <0.25 秒，或不足原音 40% | 还没读完呢 | 把尾音读完，不要只说一半；用 0.5x 跟着读 |
| 完全听错 | 识别到别的词，相似度 <0.4 | 读的不是这个词 | 先 0.75x 听，再跟着读；注意开头音 |
| 有点接近 | 0.4 ≤ 相似度 <0.7 | 有点接近了 | 用 0.5x 听，注意{开头 / 结尾 / 中间}，再读一遍 |
| 读得拖 | 降级评测时时长比 >2.5 | 读得有点拖 | 用 0.75x 连起来读，不要一字一顿 |
| 无法识别（降级） | 无设备端识别且时长比不在区间 | 再试一次 | 先 0.5x 听清，再按原速读 |

- **三步纠错法**（失败卡固定给出）：`0.5x 听清 → 0.75x 跟读 → 原速读一遍`
- **差异定位**：目标词与识别文本做最长公共前缀 / 后缀比较，归到"开头 / 结尾 / 中间"；多词短语按词对齐，指出漏掉或听错的词（例：目标 `toy plane`，听到 `toy`，提示"漏了 plane"）
- **建议配速规则**：完全听错 → 0.75x（先听清是哪个词）；有点接近 / 没读完 → 0.5x（听细节）；太小声 / 读得拖 → 0.75x（跟上节奏）；无法识别 → 0.5x 先听、原速再读
- **能力边界**：首版没有音标与音节切分数据，纠错只做到"位置 + 慢速 + 重读"，不做音素级评分；后续若补音节数据再升级（不改变现有状态机与文案结构）
- 差异提示只在识别有结果时出现；降级评测（无设备端识别）时用"这次没听清，先听一遍"替代，不留空位
- 失败卡**不显示分数**，也不展示相似度数值，只给可执行的动作

**数据写入**

| 事件 | 写入 |
|---|---|
| 评测完成（达标 / 未达标） | `Attempt(kind="speak", passed, itemCode, unitCode, sessionID)` |
| 达标 | `ItemProgress.timesSeen+1`、`timesPassed+1`、`lastSeenAt=now`、`firstPassedAt ??= now`，重算 `masteryLevel` |
| 未达标 | `ItemProgress.timesSeen+1`、`lastSeenAt=now`（不写 `firstPassedAt`） |
| 首次达标 | `StarLedger(+3, grantKey="first:<itemCode>")` |
| 每次达标 | `StarLedger(+2, grantKey="speak:<itemCode>:<yyyy-MM-dd>")`，同一 item 每天只发一次 |
| 跳过 | 只写 `Attempt(passed=false)`；不写 `ItemProgress`、不发星、不进复习调度 |
| 会话 | 进入学习页建 `LearningSession`；离开或进后台结算 `durationSeconds` 与 `newItemsLearned`（本次新增 `firstPassedAt` 的条目数） |
| 单元完成 | 不另存状态：全部条目 `firstPassedAt != nil` 即完成；+5 星走 `unit:<volume>-<unit>` 幂等（tasks 5.x） |

**「已学」与「完成」口径**

- 已学条目 = `ItemProgress.firstPassedAt != nil`；只试过没达标不算
- 首页进度条、课程列表进度、单元解锁都按这个口径
- 单元完成 = 该单元全部 word 与 sentence 都 `firstPassedAt != nil`
- 家长报告"新学单词数 / 新学句型数" = 当日首次 `Attempt(passed=true)` 的条目去重数（不是"产生过 Attempt"）

**边界与异常**

| 场景 | 处理 |
|---|---|
| 原音缺失 | 禁用「听原音」，仍可录音；无原音时长 → 跳过时长比，只靠识别 + 音量 |
| 录音中想听原音 | 播放请求直接忽略（输入优先），录音结束再播 |
| 录音 / 评测中弹出结算页、离开页面 | 取消录音、丢弃在途评测结果，不写 `Attempt` |
| 麦克风被拒 | `denied` 卡片：去设置 / 先跳过；跳过后该词不算已学，下次还会出现 |
| 连续未达标 | 默认 3 次后出现「先练下一个」，次数读 `LearningSettings`（0 = 关闭跳过） |
| 背景 / 来电 / 拔耳机 | 停止录音并丢弃半截结果，回到 `failed` 提示重试（见「音频会话与中断」） |
| 全部词已达标的单元 | 练习模式，结算用"本次达标 N 个词"，不再发首次星 |
| 学完 Unit N 后首页"当前单元"变成 N+1 | 学习页在进入时固定 unit id，不随首页数据重算换页 |

#### Decision 18: 用设备端语音识别做单词级评测，不用第三方 SDK

**选择：** `SFSpeechRecognizer(en-US)` + `requiresOnDeviceRecognition = true` 把录音转文本，与目标词做归一化编辑距离比较（≥ 0.7 算读对），音量与时长只做兜底。

**理由：**
- 录音不出设备：满足"录音只在本机、不上传"的承诺，家长可解释
- 零成本、离线可用；单词级判定不需要音素级评分
- 比"音量 + 时长"能真正区分读对 / 读错，家长报告里的"跟读达标"才有意义
- 失败可降级：老设备 / 未下载听写资源 / 无权限时退回音量 + 时长，不阻断学习

**备选：**
- 保留"听 → 说 → 认"三环节（拖拽配对）：切换成本高，且配对验证不了发音，故放弃
- 只用音量 + 时长：实现最省，但读错也能过；保留为降级路径
- 讯飞 / 百度语音评测 SDK：更准，但要联网、要授权、录音出设备，与隐私承诺冲突

**代价：** 识别依赖系统听写资源（真机一般已具备）；相似度阈值对短词（`see` / `she`）偏宽容，用"听到的是「…」"文案让家长和孩子自己判断。

**验收：**
- 读对 → 达标并自动进下一个词；读错 / 太小声 → 不达标，且文案能说清原因
- 全流程不出现准确率百分比
- 飞行模式下仍可评测（设备端识别）
- 拒绝麦克风 → 可跳过，不卡死单元
- 连续达标到本环节末尾 → 自动进入游戏；整个单元完成后才出现"Unit N 学完啦"结算页
- 退出学习页后不残留录音临时文件

### 句子学习环节（首版范围 A：核心句型）

小学英语不只记单词，每单元的核心句型同样要学、要练、要复习。首版每单元 2-3 条（二上约 18 条），与单词共用同一套进度/复习/评分表（`itemCode = "s:u1-s1"`）。

| 环节 | 做法 |
|---|---|
| 听 | 整句音频 + 文本（整句高亮，不做逐词时间戳） |
| 说 | 跟读整句，复用单词跟读评测（设备端识别 + 原音对比，降级为音量/时长） |
| 认 | **词块排序**：把打乱的 `chunks` 拖拽拼成句子 |
| 游戏 | **听音补全**：听句子，从 3 个词块里选出空缺项 |
| 复习 | 整句跟读，与单词共用间隔重复调度 |

- 句子**不强制配图**：教材情境图无授权，用「文本 + 音频 + 词块」三件套支撑练习
- 句型音频先用 TTS 生成（`sentences/{unit}/{id}.mp3`），后续可原路径替换为教材原音切片，JSON 与代码均不改
- 首版不做课文对话全文与故事（档位 B/C），列入后续内容任务

### 视觉规范
- 主色橙黄 + 辅助天蓝，圆角 16-24pt，大字号，星星/撒花动画

### 内容 JSON 格式

课文与单词收录在每个学期包的 `curriculum.json`（即原 `grade2.json`，随包内 `audio/ words/ img/` 一同下发），下载解压后读取一次并常驻内存。资源定位统一走 `ResourceLocator`：按 (学期, 相对路径) 在 `Application Support/Curriculum/<semester>/` 下查找，找不到即判定"内容未安装"并触发空状态/占位降级。

```

音频本体不放进 JSON，只在每条 word / listening 上记录相对路径（构建脚本按确定性命名规则落盘）：
- 课文原声：`audio/{docId}_{seq}.mp3`（docId/seq 来自抓取清单 `jx_audio_manifest.json`，129 个，Unit↔Period 均已对齐），专供单元页「跟我读」模块连播/逐条跟读，不进入单元流转「听」环节
- 单词发音：`words/{unit}/{wordId}.mp3`（来自 suyang123 清单，二上 33 个），进入单元流转「听」环节
- 句型发音：`sentences/{unit}/{sentenceId}.mp3`（首版 TTS 生成，二上约 18 条）；后续可**原路径替换**为教材原音切片，JSON 与代码均不改
- 配速：不做预生成副本，播放时用 `AVAudioEngine` + `AVAudioUnitTimePitch`（0.5x / 0.75x，**变速不变调**）实时变速（竞品均为运行时变速，无预生成慢速文件）
- 中文释义：JSON 保留原始词性前缀（`"v.感觉到"`），但 UI **只显示主体词义**（"感觉到"）；二年级不教音标、也不要求孩子认词性缩写，因此**首版不显示音标**（JSON 同样不设 `phonetic` 字段）

- [ ] 学期包内 `curriculum.json` 可解码为 Curriculum 模型，且 `ResourceLocator` 能从 `Application Support/Curriculum/<semester>/` 取得全部引用资产

### 音频素材落实方案

两个网络音源，一个构建脚本落盘；App 运行时无任何网络依赖：

| 素材 | 音源 | 数量 | 原始文件 |
|---|---|---|---|
| 课文原声 | 51jiaoxi（vga 接口，128kbps mp3 已验证） | 129 | `_download/jx_audio/{docId}_{seq}.mp3`（历史暂存路径） |

格式决定：
- **不转码、不重采样**：源文件本身就是 mp3（课文为已验证的 128kbps，单词为原生 mp3），AVAudioPlayer 直接解码；命名维持 JSON 章节已定的 `audio/{docId}_{seq}.mp3` 与 `words/{unit}/{wordId}.mp3`
- 单词配图与发音同源成对落盘，进 `img/u{unit}/{wordId}.png`
- 不生成慢速副本（运行时变速已定）

构建脚本 `content-service/build/build_resources.py`（Python 标准库；Node 版不再单独维护）：
1. 读取 `jx_audio_manifest.json` 与 `app/Resources/Curriculum/grade2.json`
2. 复制 129 个课文 mp3 → `app/Resources/Curriculum/audio/`
3. 复制 33 组单词 mp3/png → `app/Resources/Curriculum/words/{unit}/` 与 `img/u{unit}/`
4. 校验：grade2.json 引用的每个资产文件目标位置存在且字节 > 0，二上 33 词 / 129 课文无缺失；任一缺失脚本以非 0 退出码报清单

验收标准：
- [ ] 运行脚本后产出的学期包结构与 `curriculum.json` 引用完全一致（迁移前落 `app/Resources/Curriculum/`，迁移后为 `packs/<id>.zip`，见 tasks 7.4）
- [ ] App 内播放不打网络请求，全部本地文件

## 家长凭据与恢复策略

PIN 与恢复码都是"会被忘掉"的东西，**恢复路径必须比凭据本身更可靠**。分四层，任一层通过即可重设 PIN：

| 层 | 依据 | 能做什么 | 备注 |
|---|---|---|---|
| ① 设备密码 / Face ID | iPad 自身锁屏凭据（`LocalAuthentication`，`.deviceOwnerAuthentication` 含设备密码回退） | 直接重设 PIN | **零记忆负担**；需 `NSFaceIDUsageDescription`；建议家长给 iPad 设锁屏密码 |
| ② 6 位恢复码 | 首次设置时生成，Keychain 只存哈希 | 重设 PIN | 支持「复制」「分享到文件 App」「导出图片」；**随时可重新生成**（旧码立即失效） |
| ③ Debug 重置入口 | "家长 = 开发者"这个事实 | 仅清 PIN，**保留全部学习数据** | 仅 `#if DEBUG`；依赖 Xcode 覆盖安装不清数据容器 |
| ④ 重装清空 | — | 清空全部数据 | 极端情况，文档明示是最后手段 |

**防孩子绕过的三条约束：**

- 设备密码**只用于"忘记 PIN"流程**，不能替代日常家长验证：平时进家长 Tab 仍然要 PIN
- 家长面板记录**进入日志**（时间 + 验证方式：PIN / 恢复码 / 设备验证 / Debug 重置），设置页可查
- 设置里提供「允许用设备密码找回」开关（默认开）；关掉后只剩 ②③

**首次设置 PIN 时的检查：** 若设备未设锁屏密码 → 提示"强烈建议先给 iPad 设锁屏密码，这是唯一可靠的找回方式"，允许继续（此时 ① 不可用）。

**恢复码的保存方式**（不要只给"抄一次"）：

- 生成后提供「复制」「分享到文件 App」「存成图片」
- 设置 → 安全 → 「重新生成恢复码」：验证身份后生成新码，旧码立即失效
- PIN 与恢复码在设备上都只有 salt + 哈希，不存明文

├── serve.js                           Node 静态服务 + 扫描 packs/ 生成 manifest

    ├── g2s1.zip  g2s2.zip  ...

```

- 服务地址：`http://<host>.local:8080`（用 Bonjour 主机名，避免 DHCP 换 IP 导致失效），设置页允许手动改成内网 IP
- 只绑内网、不做端口映射；服务只提供**只读静态文件**，不上传任何设备数据（录音与进度全部留本机）

### manifest 协议

```json
{
  "contentSchemaVersion": 2,
  "packs": [
    { "id": "g2s1", "grade": 2, "title": "二年级上",
      "contentVersion": 3,
      "schemaVersion": 2,
      "sizeBytes": 55400000, "sha256": "…", "url": "/packs/g2s1.zip",
      "previous": { "sha256": "…", "url": "/packs/g2s1-v2.zip" } }
  ]
}
```

- `contentVersion` = 该学期内容版本（内容变了 +1）；`schemaVersion` / `contentSchemaVersion` = **内容结构版本**（JSON 结构变了 +1）
- `previous` 指向上一版本包：新版本内容有误时，设置页可「回退到上一版本」（学习进度按 `itemCode` 保留不变）
- 服务端 `packs/` 至少保留最近 **2 个版本**，便于回滚

### 版本兼容（内容与代码解耦的必付代价）

内容能独立更新，就一定会出现「新内容包 + 旧 App」。规则如下：

| 场景 | 处理 |
|---|---|
| App 内置 `supportedSchemaVersion`（当前 2） | 下载列表里 `schemaVersion > supportedSchemaVersion` 的学期**置灰**，标注"需要更新 App"，不发起下载 |
| `curriculum.json` 顶层也带 `schemaVersion` | 解码前先校验，不符则判定"内容不兼容"，不进入学习流程 |
| JSON 字段演进 | 新增字段一律 `Optional` 或给默认值；**不允许**把已有必填字段改名/改类型（那必须 +1 schemaVersion） |
| 解码失败（结构不兼容 / JSON 损坏） | 该学期标记为"内容不兼容"并**隔离**（不参与今日任务与复习队列），首页提示"重新下载该学期"；App 不崩溃 |

### 客户端下载流程

```
探测 manifest（2 秒超时）
   |
   v
比对本地 installedVersion / schemaVersion 兼容性
   |
   v
下载 zip -> 校验 sha256
   |
   v
解压到 .tmp/<id> -> 校验文件数 + curriculum.json 引用的资产齐全 + schemaVersion
   |
   v
原子 rename 到 Curriculum/<id> -> 记录 installedVersion 与本地清单
```

- 解压依赖 **ZIPFoundation**（SPM 依赖，MIT）：iOS SDK **没有** zip 解包 API；不采用 `AppleArchive`（`.aar` 需要在 macOS 上打包，而内容服务器是 Windows）

- 不做断点续传（局域网十几秒），失败即整包重下
- 校验不通过就删临时目录，已安装内容不受影响
- 下载前检查可用空间 ≥ 包大小 × 1.5
- 存储落在 `Application Support`，`isExcludedFromBackup = true`

## 今日任务与学习调度

每次进入「学习」Tab 首页时按下列顺序计算当日任务。规则集中在一处（`DailyPlanBuilder`），不在 View 里散写：

```
进入学习首页
   |
   v
[1] 取到期复习词: ReviewSchedule.scheduledAt <= now
   |  按到期时间升序, 一次最多 20 个
   v
[2] 逐个复习 -> 写 Attempt(kind = "review") -> 更新 ItemProgress
   |                       -> 按结果计算下次间隔
   v
[3] 今日时长预算(20 分钟)还有剩余? --否--> 今日结束(只复习, 不推新词)
   |是
   v
[4] 按课本顺序取未学新词: 仅在**当前已解锁单元**内取 words 数组顺序, 一次最多 5 个
   |  同批取该单元未学句型 1 条(先词后句)
   v
[5] 该单元全部 word 与 sentence 都首次达标(firstPassedAt != nil) -> 单元完成: +5 星, 解锁下一个单元
   |  (首页进度条按条目计: 已学条目 / 总条目, 二上 = 51 项, 单元完成不额外跳进度)
```

| 参数 | 取值 | 说明 |
|---|---|---|
| 单次复习上限 | 20 个 | 到期数量超过上限时当日只复习，不推新词，避免新词被永久挤压 |
| 每日新词上限 | 5 个 | 约等于一个单元的新词量（二上 6 单元 33 词，均 5.5 词/单元） |
| 每日新句型上限 | 1 条 | 与同日新词同批推进（先词后句），使单元时长稳定在 9-10 分钟 |
| 新词顺序 | 课本顺序，且**只在当前已解锁单元内取** | 严格线性解锁：完成一个单元才解锁下一个；未解锁单元在课程列表置灰不可点 |
| 家长手动解锁 | 家长 Tab 可把指定单元标为已解锁 | 应对"学校已教到 Unit 4、App 还停在 Unit 1"的情况；不改变星星与进度，只放行访问 |
| 单元完成判定 | 该单元每个 word 与 sentence 的 `ItemProgress.firstPassedAt != nil`（首次达标） | 跟读达标才算学过；只试过没达标不完成单元，避免"点开即完成" |
| 首页进度条 | 已学条目（`firstPassedAt != nil`）/ 总条目（二上 = 33 词 + 18 句 = 51 项） | 按条目计而非按单元计，避免"6 单元 × 10%"永远到不了 100% |
| 今日时长预算 | 20 分钟 | 与「奖励与防沉迷参数」的每日上限同源 |

- 复习环节的作答同样落一条 `Attempt`（`kind = "review"`），既驱动复习调度，也参与正确率聚合（见下节）
- 中途杀 App 后重入首页按最新数据重算，**不锁定"今日清单"**，避免任务卡死

**「今天」的边界：** 一律按**本地时区 00:00** 切分（跨午夜立即重置当日配额：20 分钟预算、每日 5 词 / 1 句、今日已发星）。不引入"学习日"或跨午夜宽限，规则越简单越不容易出错。

**「继续学习」按钮：** 永远等于"今日任务里第一个未完成的环节"，**不单独维护"上次学到哪"的游标**。这样只有一个状态源：孩子昨天学到 Unit 2 中途退出，今天首页仍是"复习 → 新词"，"继续学习"直接进入第一个未完成环节；若今日复习队列已占满 20 分钟，它就指向复习而不是新词。

**学完整册后的终态：** 当已学条目 = 总条目且今日无到期复习时，今日任务卡替换为"🎉 二上已学完"卡片，展示累计学习天数 / 总时长 / 平均正确率，并给"去下载其他学期"入口（跳设置页下载管理）。不会出现空白首页。

**卡住可跳过：** 同一环节连续失败 3 次（跟读未达标 或 连续答错）→ 出现「先跳过」按钮。跳过的行为：
- 不写 `ItemProgress`（不记为已学），不计星
- 仍写一条 `Attempt`（`passed = false`），供家长报告统计薄弱项
- 该条目顺延到下次队列，不进入复习调度

## 指标口径与数据字典

**架构决定：存明细，不存聚合。** 每次交互写一条 `Attempt`，正确率与薄弱词在读取时按口径聚合；`LearningSession` 退化为「会话边界 + 时长」。

```swift
@Model final class Attempt {
    #Index<Attempt>([\.profileID, \.at])   // 报告按"孩子 + 时间范围"高频查询
    var profileID: UUID
    var sessionID: UUID
    var itemCode: String      // "w:758201" / "s:u1-s1"
    var itemKind: String      // word / sentence
    var unitCode: String
    var kind: String          // speak / review / match / game
    var passed: Bool
    var at: Date
}

enum AccuracyRule {
    static let countedKinds: Set<String> = ["speak"]   // 唯一口径开关
}
```

- `LearningSession` 只保留 `startedAt` / `endedAt` / `durationSeconds`，**删除 `correctCount` / `totalCount` / `accuracy`**
- 改口径只动 `countedKinds` 一行，历史数据随新口径重算，不会出现"趋势图断层"
- `speak` 的每条 `Attempt` 都是一次**完整评测**；评测基础设施异常（识别超时 / 音频不可读 / 录音被打断）不写 `Attempt`
- 容量：约 35 条/天、一年约 1.2 万条，SwiftData 无压力；如需控体积按学期归档旧 `Attempt`

**默认口径（`countedKinds = ["speak"]`）：**

| 环节 | 是否写 Attempt | 是否计入正确率 | 是否发星 |
|---|---|---|---|
| 说（跟读，含认词） | 是（`speak`） | 是（默认唯一计入项） | 达标 +星 |
| 复习（翻卡跟读） | 是（`review`） | 否（默认不计入） | 按规则 |
| 认（句型词块排序） | 是（`match`） | 否（默认不计入） | 答对 +1 |
| 游戏（听音选图） | 是（`game`） | 否（默认不计入） | 答对 +1 |

**指标字典：**

| 指标 | 口径 | 数据来源 |
|---|---|---|
| 当日正确率 | 当日 `Attempt` 中 `kind ∈ countedKinds` 的 `passed` 占比 | `Attempt` |
| 条目掌握度 | 该 item（词或句）达标次数映射到 `masteryLevel`（分级规则见参数表） | `Attempt` + `ItemProgress` |
| 薄弱条目 | `timesSeen >= 2` 且 正确率 `< 0.6`（正确率同样按 `countedKinds` 计算） | `ItemProgress` |
| 新学单词数 / 新学句型数 | 当日首次产生 `Attempt(passed=true)` 的 `itemKind = word` / `sentence` 条目数，**分开统计**（只试过没达标不算） | `Attempt` |
| 单元完成度 | 已完成单元数 / 总单元数（二上 = 6）；单元完成 = 该单元全部 word 与 sentence 的 `ItemProgress.firstPassedAt != nil` | `ItemProgress` |
| 首页进度条 | 已学条目数 / 总条目数（二上 = 51 项），不按单元计；已学 = `firstPassedAt != nil` | `ItemProgress` |
| 当日学习时长 | 当日各 `LearningSession.durationSeconds` 之和 | `LearningSession` |
| 本周学习天数 | 本周内「单日累计 ≥3 分钟」的日期去重计数（不足 3 分钟不计入，避免点开即算） | `LearningSession` |

标「待确认」的项（`masteryLevel` 分级、复习间隔）已在「奖励与防沉迷参数」定稿，本节不再是待确认状态。

## 奖励与防沉迷参数

数值集中定义在一处常量文件，不散落在各 View 里。标「待确认」的尚未拍板，实现前需收敛成具体值。

| 参数 | 取值 | 状态 |
|---|---|---|
| 答对一题 | +1 星 | 已定（reward-system spec） |
| 跟读达标 | +2 星（单词与句型同规则） | 已定 |
| 完成一个学习单元 | +5 星（不额外跳进度；进度由条目数决定） | 已定 |
| 徽章目录 | 6 个：初次学习 / 连学 3 天 / 连学 7 天「坚持小达人」/ 完成首个单元 / 完成整册（6 单元）/ 跟读达标 20 次 | 已定 |
| 首次达标奖励 | 同一 `itemCode` 首次达标额外 +3 星（`grantKey = first:<itemCode>`，幂等） | 已定 |
| 每日学习时长上限 | 20 分钟（与今日任务预算同源） | 已定 |
| 每日发星上限 | 与 20 分钟联动：超时后只允许无奖励复习 | 已定 |
| 星星余额上限 | 500（达到后提示兑换，不再发星） | 已定（reward-system spec） |
| 同一奖励兑换冷却 | 3 天 | 已定（reward-system spec） |
| 兑换规则字段 | 见「奖励体系」的 `RedemptionRule` 定义（11 个字段） | 已定 |
| 复习间隔 | 1→3→7→14→30 天；答错回退一级（最低回到 1 天）；新词首次复习 = 学完次日 | 已定 |
| 掌握度分级 `masteryLevel` | 0 未学 / 1 已见 1 次 / 2 达标 1 次 / 3 达标 ≥3 次且跨 ≥2 天 / 4 达标 ≥5 次且跨 ≥3 天 | 已定 |
| 星星记账 | 流水制 `StarLedger`，余额与"今日已发"均由流水聚合，无需归零任务 | 已定（见「健壮性与合规约定」） |

**发星幂等键：** 跟读达标 `speak:<itemCode>:<yyyy-MM-dd>`（同一 item 每天一次）、首次达标 `first:<itemCode>`、单元完成 `unit:<volume>-<unit>`、复习 `review:<itemCode>:<yyyy-MM-dd>`、游戏/句型词块排序 `attempt:<attemptID>`。同一键重复触发只生效一次；所有发星仍受每日上限与余额上限 500 约束。

### 促进学习的设计原则

1. **质量型 > 数量型**：发星/奖励条件用"跟读达标 5 次""攻克 3 个薄弱词"，不用"学满 20 分钟"——后者会让孩子磨时间
2. **过程型奖励**：连续 3 天把到期复习清空 → 小奖励；直接推动复习习惯，比"学新词"更重要
3. **输出型奖励**（最推荐）：花星星换"给家长讲今天学的 3 个词""录一段朗读"——讲出来是主动回忆，记忆效果远好于再听一遍
4. **延迟满足**：大额奖励做成储蓄目标，而不是一次性全给小奖励
5. **亲子绑定**：一部分奖励必须和家长一起完成（桌游、共读、外出）；孩子真正想要的是陪玩，家长参与本身就是最强强化物

**反面清单（不做）**：奖励"学满时长"、奖励"可空刷的连续打卡"、把奖励做成随机抽奖（赌博感 + 不可预期）。

## 可调设置（家长面板）

原则：**影响孩子练习强度、但不会破坏算法的项开放给家长；算法本身（复习间隔、掌握度分级、正确率口径）不开放**，避免家长调出无法验收的状态。

| 设置项 | 默认 | 可选档位 | 生效点 |
|---|---|---|---|
| 连续失败几次出现「先跳过」 | 3 次 | 2 / 3 / 4 / 5 / 关闭 | 关闭后不出现跳过按钮，必须做对才能过 |
| 每日新词数 | 5 | 3 / 5 / 8 | 今日任务生成 |
| 每日新句型数 | 1 | 0 / 1 / 2 | 今日任务生成 |
| 单次复习上限 | 20 | 10 / 20 / 30 | 今日任务生成 |

- 「认环节每屏配对数」「每单元最少练习轮数」随「认」并入「说」而取消：单词不再拖拽配对，跟读达标即算完成
- 按 **Profile 独立保存**：新增 `LearningSettings`（一个孩子一份），两个娃强度不同互不影响
- 用**档位选择**而非自由输入，避免填出极端值；改动即时生效，首页「预计 X 分钟」随之重算
- 每日新词 / 新句型 / 复习上限仍受 20 分钟预算约束：调大也不会突破时长上限，只会挤占当天的新内容

## 健壮性与合规约定

实现时按本节的"标准做法"来，不要各 View 自行发挥。

### 音频会话与中断

| 场景 | 处理 |
|---|---|
| Category | 听/认/游戏：`.playback`（配 `.duckOthers`）；说/跟读：`.playAndRecord` + `.defaultToSpeaker` + `.allowBluetooth`。切换前后都要 `setActive` |
| 录音优先 | 录音期间所有播放请求直接忽略（播放器置 input-busy 标记），避免抢 audio session 把录音掐断 |
| 系统打断（来电/闹钟） | 监听 `interruptionNotification`：began 时暂停并保存 `currentTime`；ended 时判断 `.shouldResume` 再恢复 |
| 拔耳机/切设备 | `routeChangeNotification` 的 `.oldDeviceUnavailable` → 暂停，**不自动改走外放**（否则课堂场景会突然外放） |
| 媒体服务重置 | `mediaServicesWereResetNotification` → 重建 session、player 与 recorder，重设 category |
| 录音中被中断 / 切设备 | 丢弃本次录音、提示"再试一次"，**不留半截 `Attempt`**（保证明细干净） |

### 麦克风权限

- 首次引导 3 步**不申请任何权限**
- 第一次进「说」/「跟我读」前先展示自定义说明页（"要听你读单词，需要麦克风"），用户点"开始"后才调用 `AVAudioApplication.requestRecordPermission`
- 被拒绝：给"去设置"深链（`UIApplication.openSettingsURLString`）+ 允许"跳过跟读"，其余环节照常可学
- 无麦克风权限时正确率为 0 样本，报告显示 `—` 而不是 `0%`
- 拒绝后不再自动重复弹窗（系统也只会弹一次，重复调用无意义）

### 跟读评测权限（语音识别）

- `Info.plist` 同时声明 `NSMicrophoneUsageDescription` 与 `NSSpeechRecognitionUsageDescription`
- 说明页文案覆盖两种用途："要听你读、并把你读的转成文字和原音对比；录音与识别都在 iPad 本地完成，不上传"
- 第一次评测时请求 `SFSpeechRecognizer.requestAuthorization`；**只允许设备端识别**（`requiresOnDeviceRecognition = true`），不发起网络识别
- 拒绝 / 设备不支持设备端识别 / 听写资源缺失 → 静默降级为"音量 + 时长"，不重复弹窗、不阻断学习；家长面板可看到"本机未启用语音识别"

### 缺失资产

- 图片缺失 → 灰底占位 + `photo` 图标，不阻断流程
- 音频缺失 → 按 3 秒静音占位推进，该词标记"暂不可发音"，仍可参与认/游戏
- Debug 构建 `assertionFailure`，缺失清单同时写入本地诊断日志（设置页可查）
- 发布版**绝不因缺资产崩溃**

### 会话与奖励一致性

- `LearningSession` 创建时 `endedAt = nil`；离开学习页或 App 进后台立即结算
- 冷启动把遗留未结算会话封口：`endedAt = lastActiveAt`（UserDefaults 记录的最后前台时刻），避免时长虚高
- 时长用单调时钟（`ProcessInfo.systemUptime` 差值）计算，不受系统时间改动影响
- **星星改流水制**：`StarLedger(profileID, amount, reason, grantKey, at)`，`grantKey` 唯一（`#Unique([\.grantKey])`），如 `unit:shangce-u1`、`attempt:<attemptID>`、`daily:<yyyy-MM-dd>`
  - 余额 = `sum(amount)`；"今日已发"= 当日流水之和（因此不需要 `earnedToday` 字段与归零任务）
  - 重复发星被唯一键挡掉 → 重进结算页不会二次加分
  - 家长报告可直接列出"今天这些星是怎么赚的"

### 系统时间被改

- UserDefaults 记 `lastKnownDate`；每次启动/回前台比较，若 `now < lastKnownDate - 5 分钟` 判定为时间回拨
- 回拨后：冻结当日发星、只允许复习、首页显示"设备时间异常"
- 复习到期判定使用 `max(now, lastKnownDate)`，防止靠调时间刷复习

## 媒体库（听和看）· 原 `add-media-library` 变更

> 本节由独立变更 `add-media-library` 合并而来（原型 `prototype/proto-d.html`，规格 `specs/media-library/spec.md`）。决策编号接续本文件前面的 Decision 1–6。

### 背景

见 `proposal.md` 的 Why。这里只列影响实现方式的现状与约束：

- App 内**零课程内容**，只内置 `catalog.json`；学期包（约 50 MB）经文园局域网 Node HTTP 服务下载，ZIPFoundation 解包后完全离线。该机制已在 `ipad-elementary-english-learning` 的 `curriculum-sync` 定稿，本变更**不改它**。
- 内容路径全部走业务码字符串（`w:` 单词 / `s:` 句型），学习状态在 SwiftData，Schema 已定 **11 个 `@Model` 类型**，删除 Profile 由 `ProfileDataPurger` 逐表清理。
- 现有唯一输入通道是课本「跟我读」；音频播放已用 `AVAudioEngine` + `AVAudioUnitTimePitch`，录音 + 简单评分已存在。
- 待接入素材实测：儿歌 82 首 3.47 GB（17–133 MB/首）、绘本跟读 164 段 2.83 GB（12–19 MB/段），**共 246 项 / 约 6.30 GB**，全部为 mp4，无字幕轨、无 `.srt`。
- 家里电脑是 Windows，**当前没装 ffmpeg/ffprobe**；iOS 无原生 zip、无原生 mp4 缓存 API。

**原型：** 为了让孩子和另一位家长一次看完，媒体这 9 屏和课本原型放在同一个文件夹（路径相对仓库根），按 A → B → C → D 排列：

```
openspec/changes/ipad-elementary-english-learning/prototype/
  index.html    ← 索引（A/B/C 32 屏 + D 组 9 屏）
  proto-d.html  ← 本变更的 10 屏（D1–D10）
```

### Goals / Non-Goals

**Goals:**

- 6.3 GB 素材在**不增加安装体积、不复制整包**的前提下可用（串流优先，边下边播）
- 家里电脑关机时，已看过的内容仍可离线播放
- 媒体与课本学习彻底隔离：不污染正确率、不进复习调度、不改发星上限口径
- 家长可在一屏内回答「今天看了什么、看了多久、跟读得怎么样」

**Non-Goals（设计层面）**

- 不做码率自适应、不做 HLS、不做转码流水线
- 不做媒体与课本内容的自动关联（不把儿歌塞进某个 Unit）
- 不改既有 11 类型 Schema、不为观看进度新增 `@Model`
- 不做离线整包同步（不存在「下载整个媒体包」这个动作）

### Decisions

#### Decision 7: 媒体包「只发清单，逐项下载」，不打包 zip

**选择：** 家里电脑上建 `media/` 目录：`media.json`（约 60 KB）+ `files/...`（原始 mp4 平铺/按分部建子目录）。iPad 只先拿 `media.json`，播哪条下哪条。

**理由：**
- 6.3 GB 打成整包 zip，下载 + 解压峰值需要 **12.6 GB** 临时空间，且任一项坏掉都要重下整包
- 媒体项彼此独立，没有「必须成套才能用」的语义（一本绘本、一首儿歌都能单独看）
- 逐项下载天然支持「看到哪缓存到哪」，与 2 GB 缓存上限配合得最好

**仍然复用学期包的部分：** `schemaVersion` / `mediaSchemaVersion` 版本闸门、逐项 `sha256`、下载状态机（未请求 / 下载中 / 已就绪 / 损坏）、幂等重试。**不复用：** ZIPFoundation 解包。

**备选：** ① 整包 zip（临时空间翻倍、失败代价高）；② 分卷 zip（每卷 500 MB，仍是"必须下完一卷"，且要引入分卷拼接）；③ 塞进学期包（开学季一次要下 6.3 GB，且把「课本内容」和「兴趣内容」的版本节奏绑死）。

#### Decision 8: 串流 + 后台预取，不用 HLS，也不用 `AVAssetResourceLoaderDelegate` 做边下边缓存

**选择：** 播放走 `AVPlayer(url: http://<host>/media/files/xxx.mp4)`；同时启动一个 `URLSession` 下载任务把同一文件整体预取到 `Library/Caches/Media/`。预取完成后该项标「已下载」，之后优先播本地文件。

**理由：**
- 单集只有 12–19 MB，局域网 50 MB/s，整段预取通常 1–3 秒完成，**播完时文件早已落盘**，用户感知到的就是"边看边下"
- `AVPlayer` 原生支持 HTTP 渐进式播放，只要服务端支持 `Range` 且 mp4 的 `moov` 在文件头
- 免去 HLS 转码（246 项要跑通宵，且 Windows 侧要装 ffmpeg）
- 免去 `AVAssetResourceLoaderDelegate` 自行拼装缓存：它要处理并发 range 请求、内存与磁盘一致性、播放器 seek 越界，出错时表现为"偶发卡死"，极难排查

**代价：** 串流 + 预取同时进行，局域网瞬时占用翻倍（约 5–10 MB/s）。局域网带宽足够，且**预取并发固定为 1**（顺序队列），不会 246 项一起下。

**备选：** ① `AVAssetDownloadTask`（只支持 HLS，须先转码）；② `AVAssetResourceLoaderDelegate` 边下边缓存（省一次请求，但复杂度与故障率不成比例）；③ 纯串流不缓存（家里电脑一关就看不了，与"边下边播"的要求冲突）；④ 纯下载后播（点开要等 1–3 秒白屏，孩子会反复点）。

#### Decision 9: mp4 faststart 是串流秒开的硬前提，先检查再谈播放

**选择：** 内容管线加 `check-faststart.mjs`：直接读文件头，在**前 1 MB** 内找 `moov` box；找得到视为可流式，找不到（`moov` 在尾部）标记 `streamable: false`。

**理由：**
- `moov` 在尾部的 mp4，播放器必须先拿到文件末尾的索引才能起播 → 观众看到的是"点了没反应，等 10 秒突然开始"
- 判定只需读文件头几个 KB，不需要 ffprobe、不需要解码，纯 Node 可实现

**降级路径：** `streamable: false` 的项在清单里保留，App 对这类项改为「先下后播」（点开后显示下载进度，完成后自动播放），并在缓存优先策略里提升其权重。

**后续（不在本次）：** 若 faststart 不达标的项过多，再引入 ffmpeg `-c copy -movflags +faststart` 批量 remux（无损、每项几秒）。当前无 ffmpeg，先靠检查结果决定是否值得装。

**备选：** 不做检查，靠播放体验发现问题（孩子遇到"点了没反应"会直接放弃，且家长无法归因）。

#### Decision 10: 观看状态用设备级 JSON 文件，不新增 `@Model`

**选择：** 四个文件，都在 `Application Support/media/`：
- `media-state.json`：按 `profileID` 分组，存每项的 `positionSec` / `watchedSec` / `passedSentences` / `firstTryPassed` / `retryCount` / `lastWatchedAt`，以及按日的累计观看秒数（保留 14 天）
- `media-cache.json`：设备级缓存索引（`itemID` → 文件名、字节数、`cachedAt`、`lastAccessAt`），用于 LRU
- `media-duration.json`：设备级时长回填（`itemID` → 实测秒数），见 Decision 16
- `diagnostics.jsonl`：设备级故障日志（环形 500 条），见 Decision 17

**理由：**
- **Schema 保持 11 类型不变，零数据迁移**，`ProfileDataPurger` 的 8 张表清单不动（只需额外清掉 JSON 里该 profile 的键，一行代码）
- 数据量小（246 项 × ≤5 个字段，加 14 天日汇总），全量读写 < 100 KB，无需索引与查询
- 播放位置是**高频写入**的数据（每 5 秒一次），写 SwiftData 会带来无谓的 context 变更与磁盘 IO

**代价：** 没有事务与并发保护 → 用「单写队列 + 原子替换（写临时文件再 `replaceItemAt`）」规避；损坏时按空状态重建（丢观看位置，不影响学习进度）。

**备选：** ① 新增 `@Model MediaProgress`（Schema 11→12，需迁移，且删除 Profile 时 purger 要多删一张表）；② 每项一个 `@AppStorage` 键（246 个 UserDefaults 键，遍历困难）；③ 直接复用 `Attempt` 表（语义错位：看片不是答题，会污染正确率统计）。

#### Decision 11: 播放器自绘，不用 `AVPlayerViewController`

**选择：** `AVPlayerLayer` + 自定义控件（大号播放/暂停、进度条、返回、「跟读」按钮），播放中隐藏系统菜单。

**理由：**
- 需要儿童友好控件（按钮 ≥ 64 pt、无小字）
- 需要**限制乱拖**：只允许在已缓冲区间内 seek，避免孩子反复拖到未下载位置造成长时间等待
- 需要把「跟读」入口放在播放器内（绘本），系统控件没有位置

**代价：** 缓冲状态、错误展示、AirPlay/画中画要自己处理 → 本次**明确不做**画中画与 AirPlay，只做播放/暂停/进度/返回。

**备选：** `AVPlayerViewController`（省事，但控件不可定制、拖拽不可控、跟读入口只能浮在上面）。

#### Decision 12: 跟读发星覆盖绘本与儿歌，`grantKey` 按句幂等

**选择：** 绘本按句跟读（一段 6–10 句，逐句「听原声 → 录 → 判」）；儿歌**不整首逐句**，每首只在清单里标 **2–3 个「可跟读句」**（挑完整短语、避开 `la la la` / 拟声词 / 说唱段落），跟读通过才发星。`grantKey`：绘本 `m:<itemID>#s<句号>`、儿歌 `m:<itemID>#l<句号>`；同一句重复通过不再发星；仍受每日发星上限与星星余额上限 500 约束。

**理由：**
- 用户已定口径：不是拿视频当奖励，是「学完有奖励」；纯看不能发星 → 儿歌若没有任何可判定动作，82 首看完等于零记录，家长端只有"听了 2 分 14 秒"
- 儿歌整首逐句跟读不现实：歌词大量重复、有说唱与拟声词，判分基准不稳，而且会打断"听歌"的体验
- 只挑 2–3 个完整句，既有可判性，又能在 30 秒内做完，符合二年级注意力
- 标注成本可控：82 首 × 2–3 句 ≈ 2 小时人工，写进 `media.json` 后一次到位
- 与绘本、课本共用同一评分器与阈值，孩子感受到的"通过"标准一致

**代价：** 标注质量（文本、起止秒）直接决定孩子能不能过 → 上线前必须人工试读抽样（Tasks 10.7），通过率 < 70% 的句子重标。

**备选：** ① 每看完一条就发星（可空刷，与「不做可空刷打卡」原则冲突）；② 按观看时长发星（可挂机刷）；③ 儿歌完全不跟读、只记时长（家长看不到任何"学会"信号，已否决）；④ 儿歌整首逐句跟读（判分不稳、体验拖沓）。

#### Decision 13: 每日观看上限独立于 20 分钟学习预算

**选择：** 媒体观看分钟数**不计入**每日 20 分钟核心学习预算，单独设 5 分钟上限（家长可调 0/5/10/15/关闭）。

**理由：**
- 20 分钟预算的用途是保护「学单词（听·认·说）→游戏→句型→复习」这条闭环，看片挤进去会把跟读挤掉
- 两套预算各自可见，家长端能一眼看出"今天是学了还是只看了"

**计时口径：** 只计「正在播放」的墙钟时间，暂停 / 后台 / 缓冲不计；每 5 秒落一次盘；跨天按本地 0 点切分。达到上限时**当前条目允许播完**，之后拦截新条目（避免出现"看到一半被掐"的挫败感）。

**备选：** 计入 20 分钟（家长容易误判学习量，且孩子会用看片把预算耗光）；不设上限（与防沉迷底线冲突）。

#### Decision 14: 缓存上限 2 GB + 空间保护，缓存设备级共享

**选择：** 缓存目录 `Library/Caches/Media/`，默认上限 2 GB（可调 1/2/5），LRU 按 `lastAccessAt` 淘汰；剩余可用空间 < 1 GB 时停止预取，只串流。

**理由：**
- 6.3 GB 全量落盘会吃掉低容量 iPad 的大半存储；2 GB 约等于 110 段绘本或 130 首儿歌，够日常轮换
- 放 `Caches/` 而非 `Application Support/`：系统在空间紧张时可自行回收，不至于让 App 因"占着 6 GB"被用户删掉
- 缓存放 Caches、观看状态放 Application Support → 缓存被系统清掉只丢离线能力，不丢"看过什么"的记录（家长端仍准确）

**备选：** 不设上限（低容量 iPad 会被撑爆）；放 Documents（系统不会回收，且会被 iCloud 备份 —— 我们不做 iCloud，但仍应避免）。

#### Decision 15: 「验证」分三层，「评价」只呈现事实

**选择：** 把三件常被混在一起的事分开：

| 层 | 解决什么问题 | 手段 |
|---|---|---|
| 内容验证 | 这个 mp4 完整吗、能秒开吗、多长 | 打包期 `sha256` + `bytes` + `check-faststart.mjs`；上线前 10 条人工抽样 |
| 运行时验证 | 起播成功吗、缓冲多久、缓存写对了吗 | 起播 8 秒提示、`sha256` 校验失败隔离、故障写本地诊断日志（Decision 17） |
| 学习验证 | 孩子读对了吗 | 跟读通过（绘本按句 / 儿歌抽 2–3 句），唯一发星依据 |

**评价口径（家长端只显示这三个，不显示别的）：**

- **通过率** = 通过句数 / 总句数（原型里的「6 / 8」）
- **一次通过率** = 第一次就通过的句数 / 总句数 —— 区分"真会了"和"重试磨过去"
- **复读次数** = 同一句重读的总次数

三项全部由 `media-state.json` 现成字段（`passedSentences` / `firstTryPassed` / `retryCount`）算出，**不新增 SwiftData 模型**。

**理由：**
- 家长最容易被"看满多少分钟"误导；一次通过率才回答"是不是真会了"
- 不做分数/等级：既无法客观，也违背现有家长面板"只呈现事实"的风格
- 不新增模型 → Schema 仍 11 类型、零迁移（与 Decision 10 一致）

**备选：** ① 只显示观看时长（信息太少，看不出学会没）；② 给每段打一个 0–100 分（没有基准，纯装饰）；③ 做红黄绿/排名（会让家长拿孩子互相比较，与产品定位冲突）。

#### Decision 16: 时长由首次播放回填，不依赖 ffprobe

**选择：** `media.json` 的 `durationSec` **允许为 0 或缺失**。App 首次播放某项时取 `AVAsset.duration` 写入设备级 `media-duration.json`；家长端显示优先级：**清单值 > 回填值 > 「未看过」**。两者不一致时把差值写进诊断日志。

**理由：**
- 家里电脑是 Windows、**没装 ffprobe**，Node 侧要算时长得自己解 mp4 的 `mvhd`，多一套易错代码
- 246 项一次性探测要读 6.3 GB 文件头，而"播放过才需要知道时长"——回填天然按需
- 顺带得到一个真实数据：歌曲/绘本到底几分钟，用来决定"偏长要不要剔除"（Open Questions 第 2 条）

**代价：** 没播过的项没有时长 → 家长端显示「未看过」，不用 `0:00` 冒充；这本身也是正确信息。

**备选：** ① 装 ffprobe 批量探测（准确，但多一套工具依赖 + 246 次 IO，收益仅在"没播过也想看时长"）；② 手工抄（246 条不可维护）；③ 不显示时长（家长端信息缺失）。

#### Decision 17: 播放故障写本地诊断日志

**选择：** 以下事件写 `Application Support/media/diagnostics.jsonl`（环形，最多 500 条，含时间 / `itemID` / 模式（stream/local）/ 错误码）：起播 8 秒超时、HTTP 非 200/206、解码失败、`sha256` 校验失败、缓存写入失败。家长端既有「诊断与日志」页可查看与清空。**不上传任何地方。**

**理由：**
- 孩子遇到"点了没反应"只会放弃，家长不会去查代码；没有日志就无法回答"为什么这首打不开"
- 复用既有诊断页，不新增 UI 页面，成本只有埋点
- 只存 `itemID` 与错误码、不存完整 URL 路径 → 减少无意义的主机名与路径泄露

**备选：** ① 不记录（问题不可归因，等于永远在猜）；② 上报服务端（与"不联网、不上传"的隐私底线冲突）；③ 打系统 `os_log` 就够（家长看不到，还得连 Mac 抓日志）。

### Risks / Trade-offs

- **版权** → 素材仅存家里电脑与 iPad；`media/` 与打包输出目录必须在仓库外或 gitignore 内；README 用「本地素材目录」表述，不写具体路径；打包脚本在目标路径落在仓库内时直接报错退出。
- **`moov` 后置导致"点了没反应"** → `check-faststart.mjs` 先行体检；不达标项改「先下后播」；若占比高再考虑装 ffmpeg 批量 remux。
- **串流依赖家里电脑常开** → 已看过的走缓存；未缓存的给出明确文案「需要家里电脑开着，或先下载到 iPad」，并允许一键预取。
- **6.3 GB vs iPad 容量** → 2 GB 上限 + LRU；家长端可调；提示当前缓存占用与剩余空间。
- **观看状态 JSON 损坏** → 单写队列 + 原子替换；损坏时重建空状态，只丢播放位置，不影响学习进度与星星（星星在 SwiftData）。
- **以后接入大文件（400–800 MB/集的拼读视频）会打破假设** → 参数表与设计明确「预取并发 1、单集 ≤ 100 MB」，该场景需另立提案。
- **绘本跟读若录音评分口径与课本不一致，孩子会觉得"标准变了"** → 强制复用同一评分器与阈值（Decision 12）。
- **儿歌跟读句标注质量差，孩子一直过不了** → 只标完整短语、避开拟声词；上线前人工试读抽样 10 首，通过率 < 70% 的句子重标；仍不达标就把该首降级为"只记录观看"。
- **时长回填只覆盖播过的项** → 家长端对未播放项显示「未看过」，不以 `0:00` 冒充；需要全量时长时再考虑装 ffprobe。
- **诊断日志会写到磁盘** → 环形上限 500 条、家长端可一键清空、只存 `itemID` 与错误码不存完整路径。
- **免费签名 7 天重签** → 重签安装保留沙盒数据；若某次不得不卸载重装，缓存与观看位置会丢（学习进度同样丢，符合既有"卸载即丢失"的明示）。

### Migration Plan

分三步发布，每步都可独立回滚：

1. **清单与下载（无播放）**：服务端加 `/media` 路由 + Range；App 能拉 `media.json`、能逐项下载与校验、能显示缓存占用。此时入口可先隐藏。
2. **播放与预取**：串流 + 后台预取 + 续播 + 每日上限 + 家长端媒体设置。
3. **跟读与明细**：绘本逐句跟读 + 儿歌抽 2–3 句跟读（都发星）+ 家长端「今天看了什么」与三项评价指标。

**回滚策略：** 「听和看」入口由 `media.json` 是否可用决定——删掉本地 `media.json` 或让服务端不返回它，入口即自动隐藏，其余功能（课本学习、奖励、家长面板）完全不受影响。缓存清理走家长端「清除媒体缓存」。
