# Spec Delta

## Purpose

为 App 增加第三类只读内容——儿歌与绘本跟读视频：通过局域网串流或预取到本机播放，记录观看位置与时长，绘本可逐句跟读并按既有规则发星，家长端可设每日观看上限并查看观看明细。

## ADDED Requirements

### Requirement: 媒体包清单与版本校验

媒体内容以独立的内容包下发，包内清单 MUST 声明 `schemaVersion`、`contentVersion`、`mediaSchemaVersion` 与每个媒体项的 `sha256`。任一必需字段缺失或清单无法解码时，该媒体包 MUST 整体不启用。

#### Scenario: 校验通过的媒体包启用

- **WHEN** 媒体包下载完成，清单字段齐全，且每项 `sha256` 与实际文件一致
- **THEN** 媒体包标记为可用，「听和看」入口显示包内全部条目

#### Scenario: 结构版本高于 App 支持上限

- **WHEN** 清单的 `mediaSchemaVersion` 大于 App 支持的最高版本
- **THEN** 该媒体包显示为「需要更新 App」并置灰，不进入可播条目列表，且不删除本地已缓存文件

#### Scenario: 单项校验失败

- **WHEN** 清单可解码，但其中 3 个媒体项的 `sha256` 与实际文件不一致
- **THEN** 只有这 3 项标记为「内容损坏」且不可播放，其余 243 项正常可见可播

### Requirement: 媒体项为只读内容且不进入学习进度

媒体项 MUST 以独立业务码命名空间 `m:` 标识（如 `m:song-001`、`m:pb-l1-01`），与 `w:`、`s:` 并列且不冲突。播放媒体 MUST NOT 写入单词/句型的学习进度，也不得进入复习调度。

#### Scenario: 看完绘本不产生学习进度

- **WHEN** 孩子完整看完并跟读一段绘本
- **THEN** 不产生任何 `ItemProgress` 记录，不产生 `ReviewSchedule` 记录，课本正确率统计不受影响

#### Scenario: 业务码命名空间隔离

- **WHEN** 媒体包内出现以 `w:` 或 `s:` 开头的业务码
- **THEN** 该媒体包被判定为清单非法并整体不启用

### Requirement: 串流播放与后台预取

媒体 MUST 支持局域网串流直接起播；同一媒体项在串流播放期间 MUST 并行执行后台预取，预取完成后该媒体项 MUST 可在无网络时离线播放。距离文件头部较远的位置起播时 MUST 依赖服务端 Range 支持。

#### Scenario: 串流直接起播

- **WHEN** 孩子点开一首尚未缓存的儿歌，且家里电脑的内容服务可访问
- **THEN** 播放器在 3 秒内开始播放，画面与声音正常，进度条可拖动

#### Scenario: 断网但有缓存

- **WHEN** 家里电脑关机或 Wi-Fi 断开，孩子点开一首已预取完成的儿歌
- **THEN** 该儿歌正常播放，且界面不显示网络错误

#### Scenario: 断网且无缓存

- **WHEN** 家里电脑关机，孩子点开一首未预取的儿歌
- **THEN** 界面显示「需要家里电脑开着，或先下载到 iPad」，并提供「重试」与「返回」按钮，不显示无限菊花

#### Scenario: 预取进度可见

- **WHEN** 某个媒体项正在后台预取
- **THEN** 该条目上显示预取进度，完成后显示「已下载」标记

### Requirement: 播放位置记忆

每个媒体项 MUST 记住最近一次播放位置；再次打开时 MUST 从中断处继续。播放完成或位置处于最后 5 秒内时 MUST 清除记忆，下次从头播放。

#### Scenario: 中途退出后续播

- **WHEN** 孩子把一段绘本看到第 40 秒退出，第二天再次打开同一段
- **THEN** 播放从第 40 秒（误差不超过 3 秒）继续

#### Scenario: 看完后重新播放

- **WHEN** 孩子把一首儿歌完整听完后再次打开
- **THEN** 播放从第 0 秒开始

### Requirement: 每日观看上限

媒体播放 MUST 受每日观看上限约束，默认 5 分钟，家长可调整为 0 / 5 / 10 / 15 分钟或关闭限制。达到上限时 MUST 软性拦截并允许正在播放的这一条播完。

#### Scenario: 达到上限后软拦截

- **WHEN** 某个 Profile 当日累计观看达到上限，孩子再点开新条目
- **THEN** 界面提示「今天的看片时间用完啦」，只提供「返回」，不启动播放

#### Scenario: 正在播放的一条不被粗暴切断

- **WHEN** 播放在达到上限时正在进行
- **THEN** 当前条目允许播完，但播完后不再允许开始新条目

#### Scenario: 家长设为 0 分钟

- **WHEN** 家长把每日上限设为 0
- **THEN** 「听和看」入口仍可见（不隐藏），但任何条目点击后都只显示上限提示，不启动播放

### Requirement: 跟读评分与发星

绘本 MUST 按句跟读；儿歌 MUST 按清单标注的 2–3 个可跟读句跟读。两者 MUST 复用「说」环节的评分规则与通过阈值，只有跟读通过才发星，且 MUST 遵守既有每日发星上限与 `grantKey` 幂等规则。纯观看 MUST NOT 发星。

#### Scenario: 绘本跟读达标发星

- **WHEN** 孩子在一段绘本中跟读通过 4 句
- **THEN** 按既有「说」环节规则发放星星并记入星星流水，同一媒体项同一句的重复通过不重复发星

#### Scenario: 儿歌跟读达标发星

- **WHEN** 孩子在一首标注了 3 个可跟读句的儿歌里跟读通过其中 2 句
- **THEN** 发放 2 颗星并记入星星流水；同一首儿歌的同一句重复通过不重复发星

#### Scenario: 跟读不达标不发星

- **WHEN** 孩子跟读的录音未达到通过阈值
- **THEN** 显示「再听一次试试」，不发星，允许重试

#### Scenario: 只是看不算学习

- **WHEN** 孩子把一段绘本或一首儿歌从头看到尾但一句都没跟读
- **THEN** 不发任何星星，只在观看明细里记录时长

### Requirement: 跟读评价口径

每个媒体项 MUST 记录通过句数、首次即通过句数、复读次数，并以这几项与总句数呈现。家长端 MUST NOT 给出分数、等级、红黄绿标记或孩子之间的排名。

#### Scenario: 三项指标同时呈现

- **WHEN** 一段 8 句绘本里第 1、2 句一次通过，第 3 句重试 2 次后通过
- **THEN** 家长端显示「通过 3/8 · 一次通过 2/8 · 复读 2 次」

#### Scenario: 重看不回退历史

- **WHEN** 孩子第二天重看同一段，并一次通过第 4 句
- **THEN** 第 4 句被记为一次通过，通过句数变为 4/8，复读次数只累加不归零

#### Scenario: 不出现评价性标记

- **WHEN** 家长查看任意媒体项的明细
- **THEN** 页面上不存在分数、等级、颜色分级与排名元素

### Requirement: 时长缺失时的回填

媒体清单 MUST 允许 `durationSec` 缺失或为 0。首次播放某项时 MUST 用实际媒体时长回填本地记录；显示优先级为清单值 > 回填值 > 「未看过」。两者不一致时 MUST 记录一条诊断日志。

#### Scenario: 首次播放回填时长

- **WHEN** 播放一首清单里时长为 0 的儿歌
- **THEN** 本地写入实测时长，家长端此后显示准确时长而非「未看过」

#### Scenario: 未播放项不冒充时长

- **WHEN** 某个媒体项从未播放过且清单没有时长
- **THEN** 家长端显示「未看过」，不显示 `0:00`

#### Scenario: 清单与实测不一致

- **WHEN** 清单时长与回填值都存在且相差超过 2 秒
- **THEN** 界面显示清单值，并写一条含两个数值的诊断日志

### Requirement: 播放故障本地诊断

起播超时、HTTP 响应非 200/206、解码失败、校验失败、缓存写入失败 MUST 写入本地诊断日志，含 `itemID`、播放模式（串流/本地）、错误码与时间。日志 MUST 有上限并可由家长清空，MUST NOT 上传到任何网络位置。

#### Scenario: 起播超时记日志

- **WHEN** 点开一项后 8 秒内未起播且重试一次仍失败
- **THEN** 生成一条含 `itemID`、播放模式与「起播超时」错误码的诊断记录

#### Scenario: 校验失败记日志

- **WHEN** 下载完成但 `sha256` 与清单不符
- **THEN** 生成一条「校验失败」记录，并把该媒体项标记为内容损坏

#### Scenario: 日志不联网

- **WHEN** 断掉外网后触发一次播放失败
- **THEN** 日志在家长端可见，且没有任何请求发往局域网以外的地址

#### Scenario: 家长清空日志

- **WHEN** 家长在诊断页点「清空媒体日志」
- **THEN** 日志条数变为 0，之后发生的新事件继续被记录

### Requirement: 缓存上限与空间保护

本地媒体缓存 MUST 有上限，默认 2 GB，家长可在 1 / 2 / 5 GB 间调整。超出上限时 MUST 淘汰最久未观看项；设备剩余空间低于安全阈值时 MUST 停止预取并保留串流能力。

#### Scenario: 超出上限淘汰

- **WHEN** 预取新条目会使缓存超过上限
- **THEN** 系统按最近观看时间从旧到新淘汰，直到新增后不超上限，并清除被淘汰项的离线标记

#### Scenario: 空间不足

- **WHEN** 设备剩余可用空间低于 1 GB
- **THEN** 系统停止新的预取任务，界面提示「空间不足，只在线播放」，串流播放仍然可用

#### Scenario: 缓存为设备级共享

- **WHEN** 家里有两个孩子 Profile 先后观看同一首儿歌
- **THEN** 该儿歌只缓存一份，两个 Profile 的观看时长分别按各自 Profile 记录

### Requirement: 家长端媒体设置与观看明细

家长模式 MUST 提供媒体设置（每日上限、缓存上限、仅 Wi-Fi 预取、清除缓存）与观看明细（当日与近 7 天的条目、时长、跟读得分）。观看明细 MUST 只呈现事实，不给出好坏评价或排名。

#### Scenario: 家长调整每日上限

- **WHEN** 家长把每日上限从 5 分钟改为 10 分钟并保存
- **THEN** 新的上限立即对孩子模式生效，且写入家长操作审计日志

#### Scenario: 查看当日观看明细

- **WHEN** 家长打开「今天看了什么」
- **THEN** 列出当日每个媒体项的标题、累计时长、跟读通过句数，总时长与每日上限并列显示

#### Scenario: 清除缓存需二次确认

- **WHEN** 家长在设置里点「清除媒体缓存」
- **THEN** 弹出二次确认并说明清除后需要重新下载，确认后缓存归零、离线标记全部消失

### Requirement: 媒体素材不外传且不进仓库

媒体素材 MUST 只保存在家里电脑与 iPad 本机，MUST NOT 上传到任何网络服务，MUST NOT 打包进 App 安装包，MUST NOT 进入代码仓库或随构建产物分发。

#### Scenario: 构建产物不含媒体

- **WHEN** 构建并安装 App
- **THEN** App 包内只有清单文件，不包含任何 `.mp4` / `.mp3` 媒体文件，安装体积不因本变更增加

#### Scenario: 打包脚本拒绝写入仓库

- **WHEN** 内容打包脚本的目标路径位于代码仓库内
- **THEN** 脚本报错退出并提示改用仓库外的输出目录
